PCA: the shape hidden in your data

The geometry behind principal component analysis: how the covariance matrix encodes the shape of your data, and why eigenvectors are the natural axes to read it from.

8 May 2026

An NBA scout records three measurements for every player he is scouting: height, wingspan and reach. All three measures are highly correlated, because taller players tend to have longer wingspans and higher reaches. So in practice there are three numbers (dimensions) per player, but the data could be represented with a single dimension representing the “overall size” of the NBA player. PCA finds this dimension automatically from the data alone.

The 220 synthetic players below are drawn from that structure, and the first figure plots them in raw centimetres before anything is done to them.

Standardising the data

For computing the PCA components, we need the covariance matrix. Before computing it, we standardize each feature, so the PCA runs on the correlation matrix. The data points are standardized as

xij←xij−μjσj x_{ij} \leftarrow \frac{x_{ij} - \mu_j}{\sigma_j} xij​←σj​xij​−μj​​

where iii indexes the player and jjj indexes the feature (height, wingspan, or standing reach), μj\mu_jμj​ is the mean of feature jjj across all players, and σj\sigma_jσj​ is its standard deviation.

This step makes each variable have a mean of 0 and variance of 1. This makes the three axes comparable because otherwise the feature with the largest spread (standing reach, 11 cm) would dominate the covariance matrix. The shape of the correlation stays unchanged because standardisation only rescales the values and doesn’t distort them.

The covariance matrix: encoding shape

After standardising the three measurements, the sample covariance matrix is computed as:

Σ=1N−1X⊤X \Sigma = \frac{1}{N-1} X^\top X Σ=N−11​X⊤X

This form holds because XXX is already centered. Since each feature also has variance 1, the diagonal entries of Σ\SigmaΣ are all 1 and the off-diagonal entries are Pearson correlation coefficients. For standardized data, the covariance matrix and the correlation matrix are the same thing. Geometrically the covariance matrix encodes the shape of the data cloud. Looking at Listing 1, you can see that the sample covariance matrix is basically the same that was used to generate the synthetic data. You can see the resulting covariance matrix from Figure 2.

Eigenvectors: the natural axes of the data

An eigenvector v\mathbf{v}v of Σ\SigmaΣ satisfies

Σv=λv \Sigma \mathbf{v} = \lambda \mathbf{v} Σv=λv

Applying the matrix Σ\SigmaΣ to v\mathbf{v}v only scales the vector by a scalar λ\lambdaλ and never rotates it. These eigenvectors are natural axes for the data cloud. These eigenvectors are directions along which the data is uncorrelated, with no covariance between them (orthogonal with respect to each other). The corresponding eigenvalue λ\lambdaλ is the variance of the data projected onto that axis. Then sorting the eigenvalues λ\lambdaλ from largest to smallest gives us the principal components in order: PC1 explains most of the variance, PC2 the next most etc. All principal components are orthogonal to each other. The full decomposition is:

Σ=VΛV⊤ \Sigma = V \Lambda V^\top Σ=VΛV⊤

where V=[v1∣v2∣v3]V = [\mathbf{v}_1 \mid \mathbf{v}_2 \mid \mathbf{v}_3]V=[v1​∣v2​∣v3​] has the eigenvectors as columns and Λ=diag(λ1,λ2,λ3)\Lambda = \text{diag}(\lambda_1, \lambda_2, \lambda_3)Λ=diag(λ1​,λ2​,λ3​).

Figure 3 shows the three principal component arrows as eigenvectors, scaled by λi\sqrt{\lambda_i}λi​​ to reflect the data spread better. When rotating the 3d visual, you can see that the data cloud stretches along PC1 and PC2 and PC3 explain the remaining smaller variation.

Computing the principal components

eigenvalues, eigenvectors = np.linalg.eigh(Sigma)

# eigh returns ascending order — reverse to descending
idx = np.argsort(eigenvalues)[::-1]
eigenvalues = eigenvalues[idx]
eigenvectors = eigenvectors[:, idx]  # columns are PC vectors

explained_var = eigenvalues / eigenvalues.sum()
cumulative_var = np.cumsum(explained_var)

print(f"Eigenvalues:       {np.round(eigenvalues, 3)}")
print(f"Explained variance:{np.round(explained_var, 3)}")
print(f"\nPC1: {np.round(eigenvectors[:, 0], 3)}")
print(f"PC2: {np.round(eigenvectors[:, 1], 3)}")
print(f"PC3: {np.round(eigenvectors[:, 2], 3)}")

Dimensionality reduction

Keeping only the first kkk principal components gives a rank-kkk approximation of the data:

Zk⏟N×k=X⏟N×pVk⏟p×k,X^⏟N×p=Zk⏟N×kVk⊤⏟k×p \underbrace{Z_k}_{N \times k} = \underbrace{X}_{N \times p}\underbrace{V_k}_{p \times k}, \qquad \underbrace{\hat{X}}_{N \times p} = \underbrace{Z_k}_{N \times k}\underbrace{V_k^\top}_{k \times p} N×kZk​​​=N×pX​​p×kVk​​​,N×pX^​​=N×kZk​​​k×pVk⊤​​​

where VkV_kVk​ contains only the first kkk eigenvectors and ppp is the number of features (3 in this case). In practice, the data is first projected down to kkk dimensions, then reconstructed back into the original ppp-dimensional space. But during the reconstruction, the data is constrained to lie on a kkk-dimensional subspace, so information carried by the discarded eigenvalues is lost. Scaled by 1N−1\frac{1}{N-1}N−11​ like the covariance matrix, the reconstruction error is exactly the sum of these discarded eigenvalues:

What the scout found

PC1 captures most of the variation (~80%, see Figure 4) of the three measurements. PC1 can be thought of as an “overall size” axis. PC2 and PC3 capture the remaining ~20% of the variation. What I like about PCA is that all of this analysis could be done automatically with only the data set and a little linear algebra.
